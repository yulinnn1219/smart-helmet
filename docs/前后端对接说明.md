# 智能头盔前后端对接说明

本协议是供树莓派后端实现的建议版本，当前接口均待对接。前端默认读取模拟数据；切换接口模式后使用同源 /api/v1。树莓派负责传感器采集、本地图像与语音识别、规则判断、照明灯和风扇控制、语音播放及本地存储。前端只展示树莓派返回的结果。2026-10-06 根据 boot-programs 压缩包核对：包内没有 cloud 后台、telemetry 上报程序和 helmet_client.py。以下接口仍是待实现的建议，不是已存在的真实接口。

## 本地部署与数据链路

将 dist 目录中的静态文件复制到树莓派，由已有 Python、Node 或其他本地 Web 服务提供静态资源，同时实现 /api/v1。手机或电脑连接树莓派热点后访问树莓派本地地址。开发用 server.mjs 仅提供静态文件，不提供设备接口或数据库。

正式部署时在 dist/js/config.js 将 defaultSource 从 mock 改为 http，页面首次打开就会请求本地接口。开发预览保持 mock，避免在后端未接入时误认为实时功能已经可用。

所有字体、脚本与样式均本地提供。图像、事件截图和离线底图应使用树莓派本地路径，不依赖互联网。识别模型、语音模型和数据库由后端管理；无需在前端调用云端识别服务。

实时状态每 2 秒轮询，历史记录每 10 秒轮询；用户也可刷新事件记录。请求超时为 5 秒，相关参数集中在 dist/js/config.js。GET 可重试；写入指令不能在超时后无条件重发，建议以 clientRequestId 去重。

## 建议接口

| 方法与路径 | 响应 | 前端用途 |
| --- | --- | --- |
| GET /api/v1/snapshot | Snapshot 对象 | 当前骑行、风险、超声、识别、IMU、环境、设备、语音提醒与数据状态 |
| GET /api/v1/events | { "items": SafetyEvent[] } | 统一安全事件；三个页面按类型或 tripId 使用同一份数据 |
| GET /api/v1/trips | { "items": TripSummary[] } | 行程列表及指标 |
| GET /api/v1/trips/{id} | Trip 对象 | 所选行程轨迹与本地底图信息 |
| GET /api/v1/voice-records | { "items": VoiceRecord[] } | 语音识别文本、意图、接收和执行记录 |
| POST /api/v1/commands | VoiceRecord 对象 | 可选的指令调试入口；当前正式接口模式不提供发送按钮 |

当前列表接口要求一次返回 items 数组，事件类型、日期和行程筛选在前端完成。后续数据量增大时可在适配器扩展分页与服务器筛选，不改变页面组件。建议事件与语音记录按时间倒序返回，行程列表先返回当前行程。

错误响应使用非 2xx 状态码以及 { "code": "...", "message": "..." }。列表读取失败必须返回错误，不要将失败包装为成功的空数组。不存在的行程返回 404。接口模式下前端保留同一来源的上次成功采样并显示断连；切换来源时清空缓存，避免把模拟数据当成真实旧数据。

完整字段类型见 [types.d.ts](types.d.ts)，可复制的模拟响应见 [模拟协议示例.json](模拟协议示例.json)。示例中的目标、采样和时间仅用于展示，不是实测数据；缺失的 GPS、行程、照度、事故判定和图像时间保持 null。

## 采样封装和时间

每个实时数据组使用同一封装：

```json
{
  "value": { "distanceM": 1.5 },
  "updatedAt": "2026-10-06T05:00:00.000Z",
  "module": "online",
  "valid": true,
  "error": null
}
```

| 字段 | 含义 |
| --- | --- |
| value | 实际数据；未采集时为 null，禁止用 0 补替缺失测量 |
| updatedAt | 该数据组实际采集或判定时间，使用带时区的 ISO 8601 字符串；不能每次 HTTP 返回时把旧值改成新采样 |
| module | online、offline、error、unknown，独立描述模块状态 |
| valid | true、false、null，独立描述测量或结果有效性；未知为 null |
| error | 错误原因或 null，供页面展示 |

schemaVersion 为 "1.0"。connection.state 为 connected、disconnected 或 loading，描述数据链路；receivedAt 为最近成功接收时间，lastConnectedAt 为最后成功连接时间。请求成功但传感器未提供数据时，连接可为 connected，同时相应采样 value 为 null。

页面将正常、加载中、无数据、数据过期、连接断开、模块异常和数据无效分别显示。断连和过期会把当前风险改为“风险未知”；旧风险另标为上次更新值。模块在线但 valid 为 false 时，不能显示数据正常。

| 数据组 | 默认过期阈值 |
| --- | --- |
| 风险、超声、识别、摄像头画面、IMU | 5 秒 |
| GPS 骑行状态、设备状态 | 10 秒 |
| 光照 | 15 秒 |
| 温湿度、语音状态 | 30 秒 |

这些阈值是前端初始配置，需按实际采样周期调整。摄像头画面用 frame.capturedAt 独立判断时效，不能用识别响应的 updatedAt 替代。硬件时钟应与客户端保持同步；缺失、无效或明显位于未来的采样时间按数据无效处理。页面时间按 Asia/Shanghai 展示。

## GPS 与环境

ride.fix 为 fixed、searching 或 unavailable。当前没有 GPS 上报时使用 unavailable，speedKmh、location、durationSec、tripId 为 null，module 为 unknown，显示“未提供 GPS”和“能力未提供”；已接 GPS 但尚未定位才使用 searching，显示“未定位”。已定位且静止时 speedKmh 可为 0。durationSec 以秒为单位，distanceKm 以公里为单位，速度均为 km/h，距离为米，照度计读数为 lx（当前光敏不提供），湿度为 0–100%，温度为 °C。

environment 提供 temperatureC、humidityPct，缺少舒适度判定时 comfort 为 null。当前风扇规则只使用舱温。光敏为数字开关量，light.kind 为 binary，level 为明亮／昏暗，lux 必须为 null；不能补造照度数值。

## 风险与识别

risk.value.level 为 normal、attention、warning、high 或 unknown，reasons 为触发原因数组。风险等级由树莓派规则返回，前端没有本地距离阈值、识别置信度阈值或事故判断逻辑。当前采集源码未提供联合风险等级，level 为 unknown；alert 可表示采集程序实际触发告警，true 时显示“收到安全告警 · 尚未分级”。rear_state 为 0、无回波或没有新告警不能转成 normal。过期和断连的 alert 不作为当前告警。

vision.targets 包含目标类别、0–1 的置信度及可选检测框。框使用相对于原始画面的归一化 x、y、width、height；无框为 null。frame 包含本地 url、capturedAt、width、height。没有画面时 url 为 null；有识别结果并不代表已提供采集画面。当前相机为 640×480 JPEG，开机服务未启用上传；无实际图像时 frame 为 null，不生成采集时间。当前代码仅在告警时打印识别 JSON，没有新日志不等于已确认没有目标，网络心跳不能刷新旧识别结果的采样时间。可选 warning、latencyMs 展示告警文字和识别耗时。

ultrasound.value.distanceM 是超声探测范围内的距离。direction 当前为 rear，enabled 表示测距是否已启动，rearState 为 0、1 或 null。启动之前 enabled 为 false、distanceM 为 null，显示“尚未启动测距”；已启动但无有效回波时 distanceM 为 null、valid 为 false，显示“距离不可用”。无回波可能是超出范围，不能一律标为模块异常；实际故障时才设 module 为 error。此时前端显示“距离不可用”，不会自行认定安全。

当前协议 distanceAssociation 固定为 null；前方摄像头与后方超声探测方向不同，页面分别显示前方目标类别和后方距离，不绑定到同一目标。SafetyEvent.distanceDirection 记录探测方向，缺失方向不默认前方。后端未来建立可靠的目标与测距关联时，应扩展协议并保留关联依据，不能仅因为二者时间接近就把距离绑定到目标。

## 设备模式与反馈

lamp 与 fan 使用 Device 结构：

```json
{
  "output": "on",
  "mode": "manual",
  "source": "voice",
  "reason": "用户要求开启",
  "hardwareFeedback": null
}
```

mode 只有 auto 和 manual。source 只有 light_rule、environment_rule 和 voice，分别对应光敏规则、温度规则与语音指令。source、reason 缺失时返回 null，不能仅凭 mode 推断实际控制来源和原因。reason 给出具体触发原因，如环境昏暗、达到开启阈值或用户要求关闭。

当前控制策略按提供源码对齐：controlPolicy 为 opposite_command_restores_auto。首次开／关进入手动，同方向重复保持手动，相反口令抵消先前要求并恢复自动。当前没有独立“恢复自动”口令，演示不提供该按钮。此规则取代最初需求中的显式恢复自动规则；若后续修改硬件端须同步模拟逻辑和说明。

灯光规则：连续暗 4 秒开启、连续亮 12 秒关闭。风扇规则：舱温达到 30°C 开启、降到 28°C 关闭，中间保持先前输出。在 31.2°C 时先开风扇再关风扇，返回值可为自动模式且输出仍开启，不能按照口令文字显示已关闭。真实接口模式只展示后端返回结果；只有 MockAdapter 模拟这套规则。

VoiceRecord 可增加 resultMode、resultOutput、resultReason，保存指令当时的执行结果，不能拿当前状态补填旧记录。启动测距使用 target 为 ultrasound、intent 为 range_start，显示“采集状态已更新”；它不是灯／风扇输出。

output 表示控制输出，不能据此断言灯已亮或风扇已转动。没有独立硬件反馈时 hardwareFeedback 必须为 null；有反馈时返回实际 state 和 confirmedAt，前端才显示实际状态已确认。执行硬件只有照明灯、风扇和语音播放模块，协议不包含蜂鸣器。

VoiceRecord 独立记录 receivedAt、outputUpdatedAt、status、error 和 hardwareFeedback。接收指令、更新输出、执行失败及确认实际状态是不同阶段。失败不能伪造 outputUpdatedAt，也不能清除此前有效的设备输出。

## 语音提醒与指令

voice.value.reminders 是安全语音提醒数组，按触发时间倒序返回。每条记录包含 reason、text、triggeredAt 和 status。播放状态为 queued、playing、played、failed 或 unknown。播放进程启动不能证明实际扬声器已播放。缺少可用播放结果时 status 为 unknown，显示“播放状态未提供”。提醒的 triggeredAt 固定为真实触发时刻，不能随轮询改变。

安全提醒和设备语音控制分别记录。安全提醒展示原因、内容、时间与播放状态；设备指令展示识别文本、意图、目标及各执行阶段。语音采集、识别和播放均在树莓派离线完成。

可选调试接口 POST /commands 请求格式如下；当前前端模拟按钮只调用模拟适配器：

```json
{
  "text": "打开风扇",
  "source": "voice",
  "clientRequestId": "唯一请求标识"
}
```

## 安全事件与行程

SafetyEvent 使用稳定唯一 id，类型为 proximity、vision、sudden_brake、vibration、suspected_collision、suspected_fall。疑似碰撞与疑似跌倒不能描述为已确认事故。

事件中的时间、位置、速度、距离、识别结果、截图和提醒为发生当时的快照，缺失值保持 null。前端不会用当前 GPS、速度或画面补填历史事件。tripId 指向关联行程；没有位置的事件仍在记录列表显示，地图不补造事件点。

Trip.points 是按时间排序的 GPS 点，使用 WGS84 经纬度。前端只绘制有效坐标；短距离骑行用经纬度与纬度余弦进行轨迹示意，不是地图导航或测距引擎。里程和平均、最高速度由后端计算。

轨迹与底图独立。没有本地底图时 basemap.status 为 unavailable、imageUrl 与 bounds 为 null，仍显示轨迹、行程指标和可定位事件，并提示底图不可用。

当前支持由树莓派提供的本地矩形栅格底图：status 为 available，imageUrl 指向本地图片，bounds 给出 north、south、east、west。该图片应与声明的 WGS84 经纬度范围线性对应，前端按同一范围叠加轨迹。常见 Web Mercator 瓦片需要后端预处理或后续接入本地地图引擎，不能直接将未经处理的在线瓦片作为本协议图片。

## 后端接入顺序

先实现 snapshot 与资源封装，核对未定位、无效超声和过期采样；再接入 devices 与语音阶段、统一 events、本地行程与轨迹，最后接入画面和可选底图。硬件端需验证同方向手动保持、相反口令恢复自动、测距启动、执行失败和实际反馈。前端测试通过仅说明展示与数据逻辑符合本协议。

## 当前硬件字段和转接建议

capabilities 可声明 gps、illuminance、accidentDetection、frameUpload 和 controlPolicy。当前默认能力在 config.js 的 HARDWARE_PROFILE；未提供能力不等于模块故障。能力和采样有效、采样时效需要分别处理。

IMU 使用 accelerationG 的 x、y、z（g）、gyroDps 的 x、y、z（°/s）、accelMagnitudeG（g）。旧 acceleration 字段兼容 m/s²，禁止把 g 原值直接写入。motion、label 没有后端异常判定时为 null，前端不会生成碰撞、跌倒或急刹车结论。

下面是上报程序尚需实现的映射，不代表压缩包已生成或发送这些 JSON：

| 原始信息 | 统一结构 | 处理 |
| --- | --- | --- |
| temperature_c、humidity_pct | environment.temperatureC、humidityPct | 缺失保持 null |
| accel_g、gyro_dps、accel_mag_g | imu.accelerationG、gyroDps、accelMagnitudeG | 三轴数组按 x、y、z 转对象，保留单位 |
| light = dark / bright | light.kind = binary、level = 昏暗 / 明亮 | 不生成 lux |
| lamp_mode、fan_mode = 0 / 1 | 对应 mode = auto / manual | 模式不能代替输出、来源、原因或结果 |
| distance_cm | ultrasound.distanceM | cm 除以 100；未启动与无回波分开 |
| rear_state | ultrasound.rearState | 0 不等于确认安全；1 不证明识别出车辆 |
| voice_code = 1–5 | 灯开／关、风扇开／关、启动测距记录 | 每条口令需稳定 id 或序号去重 |
| detections[].bbox = 左、上、右、下比例 | Target.box = x、y、width、height | 宽 = 右−左，高 = 下−上 |
| warning、latency_ms | vision.warning、latencyMs | 不推导联合风险等级 |
| ts_ms | 对应采样组 updatedAt | 毫秒时间转 ISO；心跳不能刷新旧采样 |

还需补充每个模块的采集时间／错误状态、测距启用状态、控制来源、指令结果、播放结果和图片采集时间。当前蓝牙通知是一行文本，控制和识别结果主要是进程内状态或日志；应共享现有状态，不另起第二份摄像头／麦克风／控制进程。

GitHub Pages 和当前演示站只提供前端。远程实际数据显示仍需接收后台和树莓派主动上报；本地离线部署由树莓派同源提供接口。/api/telemetry 和 /ws 尚未由本包确认，前端没有假设它们可用。
